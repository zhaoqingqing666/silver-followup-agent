## 数据库表改名：CLINIC_LOCATIONS → CLINICS

需求：把 `clinic_locations` 表改名为 `clinics`。

改动清单（代码 3 处 + 测试注释 1 处 + 文档/脚本 6 处）：

- `backend/src/main/resources/schema.sql`：建表改为 `CREATE TABLE IF NOT EXISTS clinics`；
  建表前加 `DROP TABLE IF EXISTS clinic_locations;` 承担旧库升级。
- `backend/src/main/resources/data.sql:31`：`MERGE INTO clinics`（种子数据 loc-d001~loc-d006 不变）。
- `infrastructure/mock/H2FacilityGuideTool.java:27`：`FROM clinics`。
- `TravelAppointmentBindingTests.java:108`：注释同步。
- `docs/06-mock-data-design.md`（第 17、52 行）、`docs/14-database-table-data.md`（总览表第 4 行 +
  小节标题 + 头部加表名变更说明）、`docs/设计思路报告.md`（第 371、462 行）、
  `docs/tools/export_h2_snapshot.py:29`（`TABLE_PURPOSES` 键）。
- `docs/records/INTERFACE_CHANGES.md`：顶部新增 2026-09-16 条目。

技术决策：

- **没用 `ALTER TABLE ... RENAME TO`**：H2 没有条件 RENAME，脚本每次启动都跑，第二次就会报错中断。
  改用 `DROP TABLE IF EXISTS 旧表名` + `CREATE TABLE IF NOT EXISTS 新表名` + data.sql 的
  `MERGE ... KEY(id)` 重建数据，幂等且对新建库/重复启动都是空操作。
- `appointment_slots.clinic_location_id` 是**列名**，不在本次范围，原样保留。
- 已告知的风险：旧表里 id 不在 `loc-d001`~`loc-d006` 范围的自定义诊室会被删掉，
  引用它们的外键值会悬空（对应预约查院内指引会报「还没有配置院内位置指引」）。演示数据不涉及。

未做 / 待办：

- 按主公要求未在宿主机构建，容器内编译与回归测试未执行。
- `backend/target/classes/schema.sql`、`data.sql` 仍是旧内容（构建产物），
  **必须在开发容器内重新构建后端才会生效**，否则跑的还是旧 SQL。
- 后续容器内可执行：`mvn -f backend/pom.xml test -Dagent.model.enabled=false`，
  并确认启动后 `clinics` 有 6 行、旧表已消失。

坑：并行对同一文件发多个编辑会触发 `EBUSY: resource busy or locked`，
且有个别编辑报成功但实际未落盘（14 文档小节标题）。同一文件的多次编辑要**串行**，改完必须全文复查。

## APPOINTMENT_SLOTS 医院/科室改为外键引用

需求：移除 `HOSPITAL_NAME`；`HOSPITAL_ID` → `HOSPITAL` 并引用 `HOSPITALS.ID`；`DEPARTMENT` 引用 `DEPARTMENTS.ID`。

主公定的三条口径：① `department` 列名保持不变，只改语义（存 `d001` 这样的编号）；② 加**真外键**；
③ 接口契约**保持不变**（主公原话："数据库可以通过外键关联查询啊"）。

改动清单：

- `schema.sql`：`appointment_slots` 改为 `(id, hospital, department, appointment_date, appointment_time, available)`，
  `hospital`/`department` 各加 FK；旧库迁移沿用 family_contacts 的「临时兼容列」模式
  （补旧列 → 按「同院同名」把中文科室名折算成 `departments.id` → 删旧列 → 加 NOT NULL 与 FK）。
- `data.sql`：`clinic_location_id` 映射改为 `'loc-' || department`。
- `RollingAppointmentSlotInitializer`：`DepartmentSeed` 收成 `(id, hospitalId)`，INSERT 只写两个编号。
- 查询侧 6 处改为 JOIN 取中文名，**字段顺序刻意保持不变**以便 RowMapper 不动：
  `MockAppointmentTool`(3)、`H2MyAppointmentTool`、`AppointmentRecordStore`、`TravelGuideService`、
  `H2MaterialPreparationTool`、`CareCatalogRepository.availableDates`。
  工具入参仍是**中文科室名**（`WHERE d.name=?`），所以 `FollowupAgentService`/`CareBookingService` 一行没改。
- 测试 4 个文件的 INSERT 改用新列 + 科室编号；`TravelAppointmentBindingTests.seedSept8` 去掉 `hospitalName` 入参。

**关键教训（差点做错）**：主公在选项里选了"接口也改回 id"，我核查后发现 `frontend/features/` 下
**9 个文件、20 处**直接渲染 `hospital`/`department`，其中 `tasks-view.tsx:165` 和
`travel-guide-view.tsx:227` 把它们拼进了**给老人朗读的句子**；且老人端根本没有医院/科室目录接口，
前端拿不到 id→名字的映射。把证据摆给主公后他改成了「FK 关联查询」——即接口保持中文名。
**下次遇到"改接口"类需求，先把前端消费面扫干净再问，不要只看 types/domain.ts。**
