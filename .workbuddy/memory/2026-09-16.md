## 数据库表改名：CLINIC_LOCATIONS → CLINICS

需求：把 `clinic_locations` 表改名为 `clinics`。

改动清单（代码 3 处 + 测试注释 1 处 + 文档/脚本 6 处）：

- `backend/src/main/resources/schema.sql`：建表改为 `CREATE TABLE IF NOT EXISTS clinics`；
  建表前加 `DROP TABLE IF EXISTS clinic_locations;` 承担旧库升级。
- `backend/src/main/resources/data.sql:31`：`MERGE INTO clinics`（种子数据 loc-d001~loc-d006 不变）。
- `infrastructure/mock/H2FacilityGuideTool.java:27`：`FROM clinics`。
- `TravelAppointmentBindingTests.java:108`：注释同步。
- `docs/06-mock-data-design.md`（第 17、52 行）、`docs/14-database-table-data.md`（总览表第 4 行 +
  小节标题 + 头部加表名变更说明）、`docs/设计思路报告.md`（第 371、462 行）、
  `docs/tools/export_h2_snapshot.py:29`（`TABLE_PURPOSES` 键）。
- `docs/records/INTERFACE_CHANGES.md`：顶部新增 2026-09-16 条目。

技术决策：

- **没用 `ALTER TABLE ... RENAME TO`**：H2 没有条件 RENAME，脚本每次启动都跑，第二次就会报错中断。
  改用 `DROP TABLE IF EXISTS 旧表名` + `CREATE TABLE IF NOT EXISTS 新表名` + data.sql 的
  `MERGE ... KEY(id)` 重建数据，幂等且对新建库/重复启动都是空操作。
- `appointment_slots.clinic_location_id` 是**列名**，不在本次范围，原样保留。
- 已告知的风险：旧表里 id 不在 `loc-d001`~`loc-d006` 范围的自定义诊室会被删掉，
  引用它们的外键值会悬空（对应预约查院内指引会报「还没有配置院内位置指引」）。演示数据不涉及。
