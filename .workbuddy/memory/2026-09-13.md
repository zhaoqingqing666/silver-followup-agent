### 刻意保留（勿误删）
- `FactExtractor` 接口：仅 RuleFactExtractor 实现，AgentRuntime 注入具体类。经主公确认作为扩展点保留。
- 前端依赖 react-dom / react-server-dom-webpack / @vitejs/plugin-react / @vitejs/plugin-rsc：
  源码零 import，但都是 **vinext 的 peerDependencies**，必留。
- tw-animate-css / shadcn：在 `app/globals.css` 里以 `@import` 使用，非死依赖。
- TemplateAnswerGenerator、RuleConversationPlanner：分别是 LlmAnswerGenerator / LlmConversationPlanner 的 fallback，活的。
- hospitalSummary / mapMaterial / profile 等 private 方法：以 `this::xxx` 方法引用调用，扫描器易误报。
- 所有 mock/H2 工具实现：接口与实现严格一对一，Spring 按接口注入，类名不被直接引用属正常。
- WeeklyHealthReportJob：`@EnableScheduling` 在主类开启，活的。

### 结论
代码库整体干净：前端无孤儿文件、无孤儿导出（唯一"零引用"是 app/layout.tsx 的 metadata，属框架约定）；
后端 69 个 Spring bean 无孤儿；无注释掉的代码块残留；
NEXT_PUBLIC_* 五个环境变量全部在用（compose.yml ↔ 前端源码一致）。

### 项目关键事实（本次调研确认，后续复用）
- **`travel_routes` 只配 3 种交通方式**（家属开车 / 打车 / 公交），但 `RuleFactExtractor.transport()`
  认 4 种（含"步行"）→ 演示说"步行/走过去"会抛 `IllegalStateException("没有配置该交通方式的模拟路线")`。
  已写入 06 号文档第十一节 + 12.2③警示。**演示话术务必避开"步行"。**
- `family_contacts` 只有 1 条（family-001 小丽，属 user-001）→ 只有 user-001 能通知家属。
- `MockTravelTool` 起点按 `users.home_address` 精确匹配 → 只有 user-001/user-002 有住址，
  user-f001/user-v001 住址为 NULL 会抛"没有配置用户出发地址"。
- H2 为 **file 模式**（`./data/silver-agent`），数据落 `backend/data/silver-agent.mv.db`（gitignore）。
  `spring.sql.init.mode=always` 启动跑 schema.sql + data.sql。
- `ToolTraceStore.record` 是**全项目唯一 trace 下沉点**（落 tool_call_logs + 推 TurnProgress），
  所以实时进度只在这一处打点。`callTool` 是薄壳：记失败 trace 后**原样 rethrow**，不吞异常。
- `ToolPolicy` 四种判定：DENY_UNKNOWN_TOOL / DENY_SIDE_EFFECT / DENY_ROLE / ALLOW。
  `READ_ONLY`（20 条，可自动执行）vs `CONFIRMATION_ONLY`（2 条，只进状态机，绝不自动执行）。
- 号源并发安全靠 **CAS 条件更新**（`WHERE available=TRUE` + 判断影响行数），不是先查后改。
- 幂等两种范式：业务键查重（submit 用 conversation_id+user_id+CONFIRMED）、
  确定性 UUID（notify 用 conversationId+contactId+message；createReminder 同构）。
- `infrastructure/mock/` 包共 16 个类 = 15 个 `domain/tool` 接口实现 + ToolTraceStore。
  `Mock*` / `H2*` 前缀**纯历史遗留，无技术差异**，无任何代码按前缀判断。
