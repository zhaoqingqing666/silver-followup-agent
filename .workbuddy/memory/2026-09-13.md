# 2026-09-13

## Dead code 复查（第二轮）

项目：silver-followup-agent（Spring Boot 3.5.6 + vinext 1.0.0-beta.9 前端）。
全程只做静态扫描，未在宿主机构建（项目须在 Dev Container 内构建）。

### 已清理
- 删除 `frontend/next.config.ts`：Next.js 时代残留，空配置 `{}` 且 `import type { NextConfig } from 'next'`，
  而 package.json 已无 next 依赖。vinext 支持不提供 next.config（见 vinext/dist/index.d.ts 注释）。
  **需容器内 `npm run dev` 验证一次。**
- 删除 5 处未使用 import：
  - `agent/MedicalBoundaryRules.java`（HealthRecordParser，仅 Javadoc 提及）
  - `api/DemoController.java`（DemoScenario，仅 Javadoc 提及）
  - `application/demo/DemoScenarioService.java`（java.time.LocalDate）
  - `test/CareBookingServiceTests.java`（java.time.LocalDate）
  - `test/MemoFlowTests.java`（MemoParser，仅注释提及）

### 刻意保留（勿误删）
- `FactExtractor` 接口：仅 RuleFactExtractor 实现，AgentRuntime 注入具体类。经主公确认作为扩展点保留。
- 前端依赖 react-dom / react-server-dom-webpack / @vitejs/plugin-react / @vitejs/plugin-rsc：
  源码零 import，但都是 **vinext 的 peerDependencies**，必留。
- tw-animate-css / shadcn：在 `app/globals.css` 里以 `@import` 使用，非死依赖。
- TemplateAnswerGenerator、RuleConversationPlanner：分别是 LlmAnswerGenerator / LlmConversationPlanner 的 fallback，活的。
- hospitalSummary / mapMaterial / profile 等 private 方法：以 `this::xxx` 方法引用调用，扫描器易误报。
- 所有 mock/H2 工具实现：接口与实现严格一对一，Spring 按接口注入，类名不被直接引用属正常。
- WeeklyHealthReportJob：`@EnableScheduling` 在主类开启，活的。

### 结论
代码库整体干净：前端无孤儿文件、无孤儿导出（唯一"零引用"是 app/layout.tsx 的 metadata，属框架约定）；
后端 69 个 Spring bean 无孤儿；无注释掉的代码块残留；
NEXT_PUBLIC_* 五个环境变量全部在用（compose.yml ↔ 前端源码一致）。
