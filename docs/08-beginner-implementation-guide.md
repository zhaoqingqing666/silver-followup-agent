# 小白实施指南：按依赖关系搭建

> **文档版本：** v0.2 **更新日期：** 2026年9月11日
>
> 本指南按依赖关系从零搭建项目骨架，覆盖到 v0.1 的能力范围。v0.2 新增的协同照护端、双轴会话身份、健康记录与健康备忘请以 `11-agent-architecture-and-controlled-tool-calling.md`、`03-agent-workflow.md` 和 `05-api-contracts.md` 为准，本指南不重复展开。

这不是日程表，而是正确的搭建依赖。后面的步骤依赖前面的结果，不建议跳过。

## 第一步：建立项目根目录

```text
<你的工作目录>/silver-followup-agent
```

把当前文档包放入该目录，然后初始化 Git：

```text
silver-followup-agent/
├─ README.md
└─ docs/
```

## 第二步：IDEA创建后端

在 IDEA 中创建 Spring Boot 项目：

- Name：`backend`
- Location：`<你的工作目录>\silver-followup-agent\backend`
- Java：17
- Build：Maven
- 依赖：Spring Web、Validation

创建一个测试接口：

```http
GET /api/health
```

返回：

```json
{"status":"UP"}
```

此时只证明 Java 后端能启动，不接 Agent。

## 第三步：创建 React/TypeScript 前端

仓库中的 `frontend` 已经创建完成。第一版只要能：

- 打开页面。
- 调用 `/api/health`。
- 显示“后端连接正常”。

这样先验证前端、后端和跨域配置都正确。

## 第四步：固定会话响应DTO

根据 `05-api-contracts.md` 创建 `ConversationResponse`。前端先使用固定 JSON 显示：

- Agent 回复。
- 当前阶段。
- 计划步骤。
- 工具调用记录。
- 确认卡片。

这一阶段不需要大模型。

## 第五步：建立工作流骨架

先实现确定性状态：

```text
STARTED
→ COLLECTING_INFORMATION
→ PLAN_READY
→ AWAITING_CONFIRMATION
→ EXECUTING
→ COMPLETED
```

再增加异常分支。用固定规则模拟用户字段已经抽取，先验证状态转移正确。

## 第六步：实现模拟工具

按统一接口逐个实现：

1. 预约查询和提交。
2. 日程冲突检查和提醒创建。
3. 出行规划。
4. 家属通知。
5. 材料清单。

每个工具可以单独测试，不依赖大模型和页面。

## 第七步：打通第一条竖向链路

不要等所有页面和工具全部完成才联调。先打通：

```text
用户发消息
→ 后端收到消息
→ 固定识别出字段
→ 查询模拟号源
→ 返回工具记录
→ 前端显示时段
→ 用户确认
→ 模拟预约成功
→ 显示事项卡片
```

这条链路跑通后，项目骨架就是健康的。

## 第八步：接入大模型

大模型先只承担两个任务：

1. 从用户文字提取结构化字段。
2. 根据系统决定的下一步生成简短回复。

要求模型输出结构化对象，不要让 Java 从任意散文里猜字段。

后续再把只读查询工具开放给 Tool Calling。提交预约、创建提醒和通知家属仍受 Java 确认门禁控制。

## 第九步：补齐所有异常分支

依次验证：

- 缺少信息。
- 无号源。
- 日程冲突。
- 工具失败。
- 修改医院或日期。
- 取消任务。
- 医疗越界。
- 紧急情况。

## 第十步：增加适老化与附加能力

在核心闭环稳定后再增加：

- 模拟语音输入。
- 回复朗读。
- 材料拍照质量检查。
- 距离出发时间提示。

这些功能不能破坏确认门禁和四个规定场景。

## 小白常见错误

### 错误 1：先写一个超长提示词

后果：流程不可控、确认容易被绕过、异常难复现。

正确方式：提示词只负责语言任务，状态和权限由 Java 控制。

### 错误 2：Controller里完成全部业务

后果：接口、工作流、工具和回复混在一起，无法分工。

正确方式：Controller只调用 `FollowUpOrchestrator`。

### 错误 3：每人建立一个独立仓库

后果：DTO和接口版本不一致，最后很难整合。

正确方式：一个仓库、不同目录、功能分支。

### 错误 4：前端根据回复文字判断状态

后果：Agent换一句表达，页面逻辑就失效。

正确方式：后端返回 `phase`、`confirmation`、`toolCalls` 等结构化字段。

### 错误 5：最后才联调

后果：接口、日期格式和枚举同时爆出问题。

正确方式：先打通最小竖向链路，再扩展功能。
