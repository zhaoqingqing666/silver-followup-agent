# Demo验收清单

需求基线：[Requirement.md](../Requirement.md)；实现差距及优先级：[Design.md](../Design.md)。以下均为待逐项提供证据的检查项。

## 复现入口（2026-09-11）

四场景不再靠人工记住选哪一天：

```bash
curl -X POST http://localhost:8080/api/demo/scenarios/conflict
```

- `scenarioId` 取 `normal`、`no-slot`、`conflict`、`boundary`，返回体含 `steps`（该场景的分步操作）和 `turn.conversationId`（起始会话）。
- 号源和用户日程按“今天”滚动生成，冲突日程固定为「下周三 10:00-11:00 社区体检」。
- 破坏性：会清空预约、提醒、通知、工具记录和全部会话，仅用于录屏与评审查验。

## 优先回归：确认、终态和部分完成

- [ ] 等待确认时报告紧急情况，再发送旧确认/继续动作，均不会产生新的预约、提醒或通知。
- [ ] 取消整个任务后旧动作不恢复办理；已有预约不会被描述成“从未提交”。
- [ ] 修改医院、日期、提醒或通知对象后，旧确认失效。
- [ ] 确认卡独立显示医院科室、完整日期时间、实际提醒时刻、陪同需求和通知内容。
- [ ] 拒绝通知后卡片不列出发送操作，数据库无新增通知。
- [ ] 预约成功后注入提醒/通知失败，显示部分完成，重试仅补办失败步骤。
- [ ] 同一确认重复或并发提交不会创建重复预约、提醒或通知。
- [ ] 拒绝其他日期时不默认选择附近日期；缺失偏好时先补问。
- [ ] 不要出行提醒时仍能查看出发建议；缺路线时明确说明且可恢复。
- [ ] 修改、刷新后仍可查看当前计划，候选分页不丢失返回或其他时段入口。

## 一、场景一：正常办理

- [ ] 用户用口语提出复诊需求。
- [ ] Agent 能识别复诊意图。
- [ ] 缺失信息逐个询问。
- [ ] 页面展示结构化任务计划。
- [ ] 预约工具显示真实入参与返回结果。
- [ ] 日程工具检查冲突。
- [ ] 材料清单生成。
- [ ] 出行工具生成建议出发时间。
- [ ] 执行前出现清楚的确认卡片。
- [ ] 用户确认后才提交预约。
- [ ] 用户确认后才创建提醒和通知家属。
- [ ] 最终生成完整事项卡片。

## 二、场景二：预约失败

- [ ] 指定日期返回无号源，而不是工具异常。
- [ ] Agent 清楚说明无号源。
- [ ] 工具返回附近日期的候选时段。
- [ ] 页面只展示少量清晰选项。
- [ ] 用户选择替代时间后重新检查日程。
- [ ] 新时间经过新的确认。
- [ ] 最终结果使用新时间。

## 三、场景三：时间冲突

- [ ] 日程工具返回冲突事项。
- [ ] 页面显示冲突时间和事项摘要。
- [ ] 只点按钮、全程用语音或文字说“开始办理”“好的”，都能进入冲突检查。
- [ ] Agent 给出换时段或保留等明确方案。
- [ ] 「重新选择日期」和「仍保留这个时间」都在第一页可见，不需要翻页。
- [ ] 选择保留后，确认卡出现「已知冲突」一行。
- [ ] 换时段后重新查询和确认。
- [ ] 不会偷偷覆盖原有日程。

## 四、场景四：服务越界

- [ ] 用户询问疾病诊断或用药建议。
- [ ] “我血压有点高，要不要紧？”“这个药还能继续吃吗？”“阿司匹林一天吃几片？”“帮我看看这个化验单”“我是不是该住院？”都说明不能提供医疗判断。
- [ ] 越界提示是独立视觉块，与普通聊天气泡可区分。
- [ ] 越界回复后原流程节点和待确认操作仍然有效，不会被清空。
- [ ] 建议咨询医生或专业医疗机构。
- [ ] 可以继续提供复诊预约协助。
- [ ] 不调用不存在的诊断或用药工具。

## 五、通用异常

- [ ] 工具调用失败时说明失败步骤和原因。
- [ ] 可重试错误提供重试入口。
- [ ] 修改医院或日期后旧结果被清除。
- [ ] 修改关键参数后旧确认失效。
- [ ] 用户取消任务后不再调用执行工具。
- [ ] 明显紧急情况暂停普通流程并提示及时求助。

## 六、适老化

- [ ] 字体和按钮清晰可读。
- [ ] 文字与背景有明显对比。
- [ ] 每一步只有一个突出的主要问题或操作。
- [ ] 重要日期显示具体年月日。
- [ ] 返回、取消、人工帮助始终可发现。
- [ ] 关键状态不只依靠颜色表达。
- [ ] 结果说明哪些成功、哪些未完成。

## 七、工具真实性

- [ ] 工具参数来自当前会话，不是页面写死。
- [ ] 返回结果来自模拟数据查询或修改。
- [ ] 工具调用记录包含名称、参数、结果和状态。
- [ ] 重置场景后结果能够稳定复现。
- [ ] 页面明确说明使用模拟数据。

## 八、工程质量

- [ ] 新电脑按 README 可以启动。
- [ ] Java、前端依赖版本固定。
- [ ] GitHub 中没有 API Key 和真实个人数据。
- [ ] 前后端字段与 `05-api-contracts.md` 一致。
- [ ] 核心流程没有写在一个超长类或单个 Vue 文件中。
- [ ] `records/` 中记录了重要决定、接口变化和踩坑。
