# Demo验收清单

## 一、场景一：正常办理

- [ ] 用户用口语提出复诊需求。
- [ ] Agent 能识别复诊意图。
- [ ] 缺失信息逐个询问。
- [ ] 页面展示结构化任务计划。
- [ ] 预约工具显示真实入参与返回结果。
- [ ] 日程工具检查冲突。
- [ ] 材料清单生成。
- [ ] 出行工具生成建议出发时间。
- [ ] 执行前出现清楚的确认卡片。
- [ ] 用户确认后才提交预约。
- [ ] 用户确认后才创建提醒和通知家属。
- [ ] 最终生成完整事项卡片。

## 二、场景二：预约失败

- [ ] 指定日期返回无号源，而不是工具异常。
- [ ] Agent 清楚说明无号源。
- [ ] 工具返回附近日期的候选时段。
- [ ] 页面只展示少量清晰选项。
- [ ] 用户选择替代时间后重新检查日程。
- [ ] 新时间经过新的确认。
- [ ] 最终结果使用新时间。

## 三、场景三：时间冲突

- [ ] 日程工具返回冲突事项。
- [ ] 页面显示冲突时间和事项摘要。
- [ ] Agent 给出换时段或保留等明确方案。
- [ ] 换时段后重新查询和确认。
- [ ] 不会偷偷覆盖原有日程。

## 四、场景四：服务越界

- [ ] 用户询问疾病诊断或用药建议。
- [ ] Agent 明确说明不能提供医疗判断。
- [ ] 建议咨询医生或专业医疗机构。
- [ ] 可以继续提供复诊预约协助。
- [ ] 不调用不存在的诊断或用药工具。

## 五、通用异常

- [ ] 工具调用失败时说明失败步骤和原因。
- [ ] 可重试错误提供重试入口。
- [ ] 修改医院或日期后旧结果被清除。
- [ ] 修改关键参数后旧确认失效。
- [ ] 用户取消任务后不再调用执行工具。
- [ ] 明显紧急情况暂停普通流程并提示及时求助。

## 六、适老化

- [ ] 字体和按钮清晰可读。
- [ ] 文字与背景有明显对比。
- [ ] 每一步只有一个突出的主要问题或操作。
- [ ] 重要日期显示具体年月日。
- [ ] 返回、取消、人工帮助始终可发现。
- [ ] 关键状态不只依靠颜色表达。
- [ ] 结果说明哪些成功、哪些未完成。

## 七、工具真实性

- [ ] 工具参数来自当前会话，不是页面写死。
- [ ] 返回结果来自模拟数据查询或修改。
- [ ] 工具调用记录包含名称、参数、结果和状态。
- [ ] 重置场景后结果能够稳定复现。
- [ ] 页面明确说明使用模拟数据。

## 八、工程质量

- [ ] 新电脑按 README 可以启动。
- [ ] Java、前端依赖版本固定。
- [ ] GitHub 中没有 API Key 和真实个人数据。
- [ ] 前后端字段与 `05-api-contracts.md` 一致。
- [ ] 核心流程没有写在一个超长类或单个 Vue 文件中。
- [ ] `records/` 中记录了重要决定、接口变化和踩坑。
