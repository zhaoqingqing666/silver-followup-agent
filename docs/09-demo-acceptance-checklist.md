# Demo验收清单

> **文档版本：** v0.2
> **更新日期：** 2026年9月11日

需求基线：[Requirement.md](../Requirement.md)；实现差距及优先级：[Design.md](../Design.md)。以下均为待逐项提供证据的检查项。

## 优先回归：确认、终态和部分完成

- [ ] 等待确认时报告紧急情况，再发送旧确认/继续动作，均不会产生新的预约、提醒或通知。
- [ ] 取消整个任务后旧动作不恢复办理；已有预约不会被描述成“从未提交”。
- [ ] 修改医院、日期、提醒或通知对象后，旧确认失效。
- [ ] 确认卡独立显示医院科室、完整日期时间、实际提醒时刻、陪同需求和通知内容。
- [ ] 拒绝通知后卡片不列出发送操作，数据库无新增通知。
- [ ] 预约成功后注入提醒/通知失败，显示部分完成，重试仅补办失败步骤。
- [ ] 同一确认重复或并发提交不会创建重复预约、提醒或通知。
- [ ] 拒绝其他日期时不默认选择附近日期；缺失偏好时先补问。
- [ ] 不要出行提醒时仍能查看出发建议；缺路线时明确说明且可恢复。
- [ ] 修改、刷新后仍可查看当前计划，候选分页不丢失返回或其他时段入口。
- [ ] 健康数值明显异常时先反问老人（重测还是照记），未确认前不写入数据库。

## 一、场景一：正常办理

- [ ] 用户用口语提出复诊需求。
- [ ] Agent 能识别复诊意图。
- [ ] 缺失信息逐个询问。
- [ ] 页面展示结构化任务计划。
- [ ] 预约工具显示真实入参与返回结果。
- [ ] 日程工具检查冲突。
- [ ] 材料清单生成。
- [ ] 出行工具生成建议出发时间。
- [ ] 执行前出现清楚的确认卡片。
- [ ] 用户确认后才提交预约。
- [ ] 用户确认后才创建提醒和通知家属。
- [ ] 最终生成完整事项卡片。

## 二、场景二：预约失败

- [ ] 指定日期返回无号源，而不是工具异常。
- [ ] Agent 清楚说明无号源。
- [ ] 工具返回附近日期的候选时段。
- [ ] 页面只展示少量清晰选项。
- [ ] 用户选择替代时间后重新检查日程。
- [ ] 新时间经过新的确认。
- [ ] 最终结果使用新时间。

## 三、场景三：时间冲突

- [ ] 日程工具返回冲突事项。
- [ ] 页面显示冲突时间和事项摘要。
- [ ] Agent 给出换时段或保留等明确方案。
- [ ] 换时段后重新查询和确认。
- [ ] 不会偷偷覆盖原有日程。

## 四、场景四：服务越界

- [ ] 用户询问疾病诊断或用药建议。
- [ ] Agent 明确说明不能提供医疗判断。
- [ ] 建议咨询医生或专业医疗机构。
- [ ] 可以继续提供复诊预约协助。
- [ ] 不调用不存在的诊断或用药工具。

## 五、场景五：代家属预约

- [ ] 入口先选身份：家属 / 志愿者进入协同照护端；就诊人本人进入就诊人端。
- [ ] 协同首页显示我协同的长辈；绑定多位长辈时先选定这一轮服务谁。
- [ ] 助手能按服务对象查询长辈的复诊安排、材料与就诊动态。
- [ ] 代约确认卡列出「服务对象」与「代约归属」，且**不问**「通知哪位家属」。
- [ ] 代约确认后才写入长辈名下的预约，并通知其他照护者。
- [ ] 长辈名下已有进行中的预约时先拦下，给出「先取消已有预约」的路，不会重复预约。
- [ ] 让助手给长辈留提醒（如「提醒我妈明天带身份证」），落到长辈自己的备忘且标明是谁留的。
- [ ] 越权访问未绑定的长辈时明确拒绝，不返回其信息。

## 六、通用异常

- [ ] 工具调用失败时说明失败步骤和原因。
- [ ] 可重试错误提供重试入口。
- [ ] 修改医院或日期后旧结果被清除。
- [ ] 修改关键参数后旧确认失效。
- [ ] 用户取消任务后不再调用执行工具。
- [ ] 明显紧急情况暂停普通流程并提示及时求助。

## 七、适老化

- [ ] 字体和按钮清晰可读。
- [ ] 文字与背景有明显对比。
- [ ] 每一步只有一个突出的主要问题或操作。
- [ ] 重要日期显示具体年月日。
- [ ] 返回、取消、人工帮助始终可发现。
- [ ] 关键状态不只依靠颜色表达。
- [ ] 结果说明哪些成功、哪些未完成。

## 八、工具真实性

- [ ] 工具参数来自当前会话，不是页面写死。
- [ ] 返回结果来自模拟数据查询或修改。
- [ ] 工具调用记录包含名称、参数、结果和状态。
- [ ] 重置场景后结果能够稳定复现。
- [ ] 页面明确说明使用模拟数据。

## 九、多模态（2026-09-11 新增）

- [ ] 助手页点「拍照」或「相册」选图，气泡里出现缩略图，可以点掉重选；最多 3 张。
- [ ] 配了 `DASHSCOPE_API_KEY`：图片回复里说得出图里的药品名、规格或材料名，`toolTraces` 里能看到 `vision.recognize`。
- [ ] 没配 key：回复是「图片识别功能暂时没有开启」，页面不报错、其余功能照常可用。
- [ ] 问「阿司匹林是干嘛的」：药名、规格、用途来自 `drug-knowledge.json`，查不到的药如实说没有。
- [ ] 按住麦克风说话：有音量条、能上滑取消；松手后出现的语音条点一下听到的是自己刚才的原话。
- [ ] 说话的同一轮必须朗读回复，即使关了自动朗读；点喇叭能停。
- [ ] 材料清单每行能「拍照 / 相册」确认，状态变成「拍照确认」；刷新后仍在。
- [ ] 拍过照的那一行点「看照片」能看回原图，点「关闭」退出。
- [ ] 换一位用户去取同一条预约的材料照片，被拒绝（404 或 400），拿不到图。

## 十、会话收尾与长期记忆（2026-09-11 新增）

- [ ] 助手页点「历史记录」：浮层里能看到刚才聊过的几段，新的在前，带相对时间、消息条数和状态徽标。
- [ ] 点「新对话」：当前这段被结束，界面回到开场；旧的那段仍能在历史记录里点回来。
- [ ] 打开一段**已结束**的会话：消息照常显示，输入框换成只读说明和「开始新的一段对话」按钮；对着它发消息、点确认卡都被拒。
- [ ] 被拒之后回到历史记录：这段会话**没有**多出「已经结束」的复读气泡。
- [ ] 刷新页面：回到刷新前那一段；若那一段已结束，则开一段新的，而不是掉进只读页。
- [ ] 「我的」页「助手记住的事」：办成一单预约后出现常去的医院、科室与时段。
- [ ] 尚未确认的草稿**不会**被记住。
- [ ] 换一家医院再办一单：旧的偏好被覆盖，不是两条并存。
- [ ] 点「忘掉这条」→「确定忘掉」：该条消失；再开一段新对话，助手不再提起它。

## 十一、办理过程可见（2026-09-11 新增）

- [ ] 助手处理一轮时，「查看办理过程」卡片上出现跳动的步骤条，逐条长出「正在理解」「正在决定要不要查东西」「调用工具：…」「拿到结果：…」。
- [ ] 卡片上显示的工具参数是**本次这轮**模型生成的（换一句话再问，参数跟着变），不是固定文本。
- [ ] 工具结果显示的是真实查询结果（换医院/科室，结果跟着变）。
- [ ] 这一轮结束后卡片自动收起，回到摘要形态。
- [ ] 卡片里不出现图片 base64、完整手机号或 `sk-` 开头的串。
