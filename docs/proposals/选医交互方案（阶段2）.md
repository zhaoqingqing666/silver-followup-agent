## 一、目标行为（已拍板的 6 条规则，实施时逐条验收）

| # | 规则 | 来源 |
|---|---|---|
| R1 | 老人指定日期要专家号而当日没有：明说「当日无专家号」→ 主动推荐 **7 天内最近**的专家号并询问是否查看；7 天内没有 → 建议改普通号或等放号。**绝不静默改日期** | 用户决定 #1 |
| R2 | 推荐排序：**可预约优先 → 匹配号型优先 → 职称优先 → 就近日期优先 → 上午时段优先**；`fee_cents` 只作同档位内的次要因子（同科室+同职称+同号型+相近日期时低价优先） | 决定 #2 + #5 |
| R3 | 口播（`speechText`）只播简化信息：**日期时段 + 姓氏职称 + 预估自付**；不读全名、不优先播原价；卡片/文字展示完整信息；**单轮最多 2 个候选号源** | 决定 #3 |
| R4 | 入口差异化：老人语音助手 = AI 自动推荐、不强制记忆医生；家属代约 Web = 开放医生筛选、可指定医生 | 决定 #4 |
| R5 | 同 R2 的价格口径（并入 R2 实现） | 决定 #5 |
| R6 | 选好科室 + 日期后，助手先报「这天该科室有哪些医生出诊（号别 + 挂号费）」；老人**点名医生**时才只列该医生的号源 | 用户补充 |

硬约束不变：预约 / 改期 / 取消等**写操作一律过确认门禁**（C-02、DEC-002、DEC-012）。阶段 2 只动「推荐与呈现」，门禁一行不碰。

## 三、交互设计（老人语音助手）

### 3.1 漏斗不变，两处加料

```
科室 → 日期 ──→ 上午/下午 ──→ ≤2 个打包候选 ──→ 确认（门禁）→ 成功
              │                │
              ├ R6：报当日出诊医生     ├ R2：排序后取前 2
              │  （号别+挂号费）        │  按钮文案=时间+医生+号别
              └ R6'：点名医生→只列他    └ R3：speechText 口播简化
```

- **不新增步骤**（用户已拍板）。日期确定时在 `periodSummary` 里**追加一句**当日医生概况（如「周三心内科出诊：张建国主任医师（专家号 ¥40）、李秀英主治医师（普通号 ¥25）」）；老人点名医生 → `state.doctorId` 锁定，后续所有候选按医生过滤。
- `recommendPeriod` 改为：按时段过滤 → 排序（3.2）→ 取前 **2** 条 → 两条 `SELECT_SLOT` 快捷回复（文案带医生与号别）+「看看其他时段」。默认推荐第一条，语气与现在一致。

### 3.2 排序器（纯函数，独立可测）

新增 `application/SlotRecommender`（静态方法 + 注入的Comparator 链），规则即 R2：

```
1. 都是可预约的（查询层已保证，防御性保留）
2. 号型匹配：用户要 EXPERT 时 EXPERT 在前；没要求时不惩罚
3. 职称：主任医师 > 副主任医师 > 主治医师
4. 日期近者前（跨日推荐场景用）
5. 同日上午先于下午
6. 同档位（同科室+同职称+同号型+日期相邻≤1天）内 fee_cents 低者前
```

每条规则一个单测，不挂在 Spring 上下文上。

### 3.3 无专家号（R1）

触发条件：`state.wantsExpert == true`（老人说了「专家」且被抽取，或点名了专家医生）且当日候选无 EXPERT：

1. 回复明说「X月X日当日无专家号」；
2. 只读查询未来 7 天该科室 EXPERT 号源（`queryUpcomingSlots` + 过滤，或新增 `appointment.queryExpertSlots`，倾向前者、少注册一个工具）；
3. 有 → 报**最近一天**（R2 排序取第一），问「要不要看这天」——用户确认才 `SET_DATE`，**绝不静默换日期**；
4. 7 天无 → 「7 天内没有专家号，可以先约普通号，或等新的专家号放出」，给「改约普通号 / 保持日期」两个选项。

### 3.4 点名医生（R6 后半）

- `ExtractedFacts` 加 `doctor` 字段；`AgentSystemPrompt` 意图说明里教模型抽取「姓氏 + 职称 / 全名」。
- 匹配策略：全名精确 → 姓氏 + 在诊 → 姓氏唯一；匹配失败不说「查无此人」，改为报当日医生清单让老人挑（适老兜底）。
- 点了医生后：只列该医生号源；该医生当天没出诊 → 报他**下一个出诊日**（生成器 `openWeekdays` 是纯函数，可直接算）。

### 3.5 口播简化（R3）

- 推荐候选轮生成独立 `speechText`：`「9月16日周三上午9点，张主任医师，专家号，预估自付40元」` 格式——日期时段 + 姓氏+职称 + 预估自付；**不读全名、不读原价对比**。
- `reply` / 卡片保持全量（医生全名、职称、号别、原价、自付）。
- 实现落点：`respondWithPlan` 的推荐分支传 `speechText`；确认门禁轮已有分离先例，口径对齐它。
- 「单轮 ≤2 候选」由 3.1 的取前 2 保证，数据层与 UI 层都不出现第三条。

## 六、测试计划

新增/扩展用例（后端，全绿目标 = 除已知 `HealthReportTests` 抖动外）：

1. **排序器单测**：R2 六条规则各一例，不依赖数据库；
2. **无专家号**：当日无 EXPERT → 回复含「无专家号」且给出 7 天内最近专家日；`state.date` 不被改写；7 天全无 → 降级话术；
3. **打包候选**：推荐轮 ≤2 条；按钮文案含医生与号别；上午同时刻两条不再重复文案；
4. **点名医生**：全名/姓氏命中只列该医生；未出诊报下一个出诊日；匹配失败兜底列清单；
5. **口播**：推荐轮 `speechText` 含姓氏职称与「预估自付」、不含医生全名、不含原价字样；
6. **门禁**：SELECT_SLOT 后仍必须走确认（既有用例回归，防新漏斗绕过）；
7. 前端 `tsc --noEmit`。

## 八、风险与边界

- **模型抽取医生名的准确性**：LLM 可能抽错姓氏 → 兜底是「匹配失败就报当日医生清单」，永远有可用出口，不会死循环；
- **`speechText` 改动范围**：只动推荐候选轮，其他轮沿用「reply 同文」现状，避免波及全部对话；
- **不静默换日期**（R1）与现有 `acceptAlternative`「接受附近日期」机制并存：前者只针对「要专家号」，后者仍是通用兜底，互不覆盖；
- 阶段 2 **不新增**写路径，确认门禁语义零变化。
