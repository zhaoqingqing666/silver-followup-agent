# 参赛文档维护说明

## 三个文件的职责

- `报名解决方案.md`：企业命题组报名材料，重点说明问题、总体方案、竞争优势、可行性和推广价值。
- `设计思路报告.md`：技术设计正文，覆盖需求分析、用户角色、智能体架构、任务拆解、工具、确认、异常、适老化、安全、创新和应用价值。
- `参赛文档维护说明.md`：只说明协作方法，不属于比赛正文。

## 更新顺序

1. 功能负责人先更新代码、接口文档和 `records/PROGRESS.md`。
2. 文档负责人判断改动属于报名解决方案还是设计思路报告，再修改对应正文。
3. 已实现、正在完善和后续规划必须分开表述。
4. 现阶段只提交 Markdown 和图片；内容定稿后再统一导出 Word 或 PDF。

## 在 VS Code 中编辑

直接打开对应 `.md` 文件修改文字，按 `Ctrl+Shift+V` 打开 Markdown 预览。

报名解决方案图片放入 `docs/assets/solution/v0.2/`，设计报告图片放入 `docs/assets/design-report/v0.2/`。在正文需要显示图片的位置单独写一行：

```markdown
![图 1 助手页任务暂停与恢复界面](assets/design-report/v0.2/assistant-page.png)
```

图片使用 PNG 或 JPG，并与 Markdown 一起提交 Git。不要使用聊天临时路径、个人绝对路径或网络链接，也不要包含 API Key、完整手机号和无关个人信息。

## Git 协作

同一时间分别指定一名成员维护报名解决方案、一名成员维护设计思路报告。其他成员把实现证据补充到 `records/PROGRESS.md`，由文档负责人统一吸收，避免多人同时修改同一个长文件。

建议提交信息：

```text
docs: update solution and design report v0.2
```

Word 和 PDF 无法像 Markdown 一样逐行合并。最终导出应由一名成员统一完成，老师在 Word 中的批注意见需要同步回对应 Markdown 正文。

## 发布前检查

- 确认导出对象是“报名解决方案”还是“设计思路报告”，不得合并成一份。
- 设计思路报告 PDF 原则上不超过20页，报名文件不超过20MB。
- 工具名称、接口字段和测试数量与当前代码一致。
- 报告、PPT、录屏和四组演示场景使用同一组事实与数据。
- 图片清晰，且不包含密钥和隐私信息。
- 上传后重新下载并逐页检查。
