# Agent 工作流

## 一轮处理

系统不使用持续运行的死循环。用户每发送一次自由语言，就触发一轮：

1. 根据 conversationId 加载会话状态与最近 8 条消息。
2. 把当前日期、当前节点、已知信息和最近消息交给 DeepSeek。
3. DeepSeek 输出结构化意图、字段变更、时间和简短理解反馈。
4. Java 校验并更新 ConversationState。
5. Java 决定补问、展示计划、调用工具或等待确认。
6. 工具结果写入 H2 和 TOOL_CALL_LOGS。
7. 保存本轮状态与消息，等待下一次输入。

自由文字和语音转文字走 POST /api/agent/messages，每轮调用一次模型；明确按钮走 POST /api/agent/actions，不调用模型；确认按钮走 POST /api/agent/confirmations。

## 预约主流程

识别复诊意图 → 补齐信息 → 展示七步任务计划和材料清单 → 查询号源 → 用户选择 slotId → 检查日程冲突 → 计算出发时间 → 查询家属 → 展示确认卡 → 用户确认 → 提交预约 → 创建提醒 → 通知家属 → 事项页显示真实记录。

## 异常分支

- 无号且接受附近日期：查询前后 3 天，展示日期和时间。
- 无号且不接受换日期：提供重新选日期、换医院、稍后再查。
- 日程冲突：提供同日其他号源、重新选日期或明确保留。
- 修改医院或日期：清除受影响的号源和出行结果。
- 紧急情况和医疗越界：安全规则拦截，不进入普通预约工具流。

## 关键文件

- ConversationState.java：当前流程字段。
- ConversationStore.java：会话状态和对话持久化。
- DeepSeekFactExtractor.java：携带上下文调用模型。
- FollowupAgentService.java：流程编排、确认门禁和工具选择。

## 日期后的时段选择细化（2026-09-03）

日期确认后立即调用 appointment.querySlots。有号时先汇总上午/下午数量和最早时间，再询问用户偏好；模型理解自然语言偏好，Java 只能从工具返回列表中推荐和选择。选定具体号源后再补齐陪同、提醒、交通、家属通知等信息，展示任务计划并进入最终确认。
