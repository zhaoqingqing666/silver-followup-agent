# 最低页面与交互组件设计

## 先区分“页面”和“组件”

成熟项目不会为每个小动作创建一个新页面。这个 Demo 建议只有 3 个正式页面，预约时段、确认、冲突处理等都作为主工作台中的独立组件出现。这样既能展示完整流程，又不会让老年用户频繁跳转。

## 一、至少需要的 3 个页面

### 页面 1：演示入口页 `/`

目的：选择模拟用户和稳定复现比赛场景，不是传统登录系统。

最低内容：

- 产品名称和一句话说明。
- “开始办理复诊”主按钮。
- 当前模拟用户摘要，如姓名、住址、家属联系人。
- 演示模式下的场景选择：正常办理、无号源、日程冲突、越界问题。
- 明确标注“本系统使用模拟数据，不连接真实医院”。

为什么建议保留：录屏时可以快速进入指定场景，评委也能看懂模拟环境。不要开发注册、密码找回、验证码等与命题无关的功能。

### 页面 2：复诊助手工作台 `/assistant/:conversationId`

这是项目的核心页面，绝大多数 Demo 都在这里完成。

布局建议：

```text
┌──────────────────────────────────────────────────────────┐
│ 银发复诊助手     模拟环境     返回 / 取消 / 人工帮助     │
├────────────────────────────────┬─────────────────────────┤
│                                │ 办理计划                │
│ 对话区                         │ ① 补齐信息   已完成     │
│                                │ ② 查询号源   进行中     │
│ 用户消息                       │ ③ 检查日程   等待中     │
│ Agent 回复                     │ ④ 规划出行   等待中     │
│ 时段选择 / 异常方案            │ ⑤ 提醒通知   等待中     │
│                                ├─────────────────────────┤
│ [按住说话] [输入消息] [发送]   │ 工具调用过程            │
└────────────────────────────────┴─────────────────────────┘
```

工作台包含的组件：

1. `ChatPanel`：消息列表。
2. `MessageInput`：文字输入。
3. `VoiceInputButton`：模拟语音或真实浏览器语音转写。
4. `PlanPanel`：显示计划步骤及状态。
5. `SlotSelector`：显示可预约时段。
6. `ConflictCard`：显示日程冲突和替代选择。
7. `ConfirmationCard`：关键操作确认。
8. `ToolCallPanel`：展示工具名、参数、结果和耗时。
9. `BoundaryAlert`：医疗越界和紧急情况提示。
10. `HelpActions`：返回、取消、人工帮助。

### 页面 3：办理结果页 `/tasks/:taskId`

目的：办理完成后让用户再次确认最终结果，也用于录屏收尾。

最低内容：

- 办理状态：全部完成、部分完成或已取消。
- 预约时间。
- 医院和科室。
- 材料清单。
- 建议出发时间和交通方式。
- 提醒创建状态。
- 家属通知对象和状态。
- “返回助手”“修改计划”“打印/保存卡片”按钮。

如果时间或能力有限，“打印/保存”可以只做页面按钮和浏览器打印，不必生成复杂文件。

## 二、不是独立页面，但必须设计的关键组件

### 1. 预约时段选择卡片

显示：

- 日期。
- 上午/下午。
- 医生或门诊类型（可以使用模拟名称）。
- 剩余号源状态。
- 选中后的明显反馈。

不要一次展示几十个按钮。每次显示 2 至 4 个推荐时段即可。

### 2. 操作确认卡片

必须显示：

- 即将执行什么操作。
- 医院和科室。
- 日期与时间。
- 是否创建提醒。
- 是否通知家属以及通知谁。
- 操作影响。

按钮使用：

- 主按钮：“确认办理”。
- 次按钮：“返回修改”。

不能使用含义模糊的“好的”“我知道了”。

### 3. 工具调用记录

每条记录显示：

```text
工具：appointment.querySlots
参数：医院、科室、期望日期
状态：调用成功
结果：找到 2 个可预约时段
```

普通用户默认看摘要；录屏时可以展开 JSON 详情，证明不是预设对话。

### 4. 最终事项卡片

这是一个可复用组件，不负责调用 Agent。它只接收后端返回的数据：

```ts
interface TaskCardViewModel {
  taskId: string
  status: 'COMPLETED' | 'PARTIAL' | 'CANCELLED'
  appointmentTime: string
  hospital: string
  department: string
  materials: MaterialItem[]
  departureTime: string
  transportMode: string
  reminderStatus: string
  familyNotificationStatus: string
}
```

`userId` 属于会话上下文，不应成为事项卡片必须知道的参数。

## 三、适老化页面规则

- 主要正文保持清晰大字号，关键日期和状态进一步放大。
- 背景与文字使用高对比配色。
- 一次只突出一个主按钮。
- 一次只询问一个主要问题。
- 不依赖悬停才能看到重要信息。
- 重要结果同时使用文字、图标和状态，不只依赖颜色。
- 始终能找到返回、取消和人工帮助。
- 日期既显示“下周三”，也显示具体年月日。
- 操作成功后明确说明“什么已经完成、什么没有完成”。

## 四、可以后加，但不属于最低页面的功能

- 材料拍照检查：作为材料清单卡片中的“拍照检查”入口，不需要单独开发完整影像系统。
- 语音播报：在 Agent 回复旁增加“朗读”按钮。
- 倒计时提醒：结果卡片显示距离出发时间，不需要后台真实定时推送。
- 家属端页面：比赛只要求模拟通知，最低版本不需要再开发一套家属 App。
